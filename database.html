Database

Overview

The pipeline writes a SQLite database at db_path in config/pipeline.yml (default results/stability.sqlite). Bulky results – loadings, scores, diagnostics, raw model objects, projections – are files under stability_artifacts/<dataset_id>/ next to it, referenced by paths relative to the DB’s directory, so the two move together.

It is a derived output. Every row is rebuilt from the targets store; nothing is edited by hand and there are no migrations.

  • db_<dataset> (write_dataset_db(), R/targets/db_write.R) writes everything about one dataset in one transaction.
  • db_cross_dataset (write_cross_dataset_db()) then writes the tables linking two datasets (projections, gene-space agreement) and deletes artifact files no row references.
  • Other targets produce rows keyed by fit_key (dataset + method + parameters); the writers resolve keys to integer ids. Fits are upserted on fit_key, so a fit keeps its fit_id across rewrites.

Schema versioning. The schema is R/db/schema.sql and R/db/views.sql; open_stability_db() (R/db/connect.R) creates them on a new file and stamps PRAGMA user_version with SCHEMA_VERSION. It refuses a DB with a different version. After any schema change, bump SCHEMA_VERSION, delete the DB and its stability_artifacts/, and run tar_make(); only the ingestion and DB targets rerun.

What it holds. The schema-1 build of 30 datasets (2026-10-05) had 7,990 fits in 3.6 GB; the largest tables were match_scores (8.9 M rows), gene_modules (3.3 M), factor_matches (3.0 M) and enrichment_results (2.1 M). Schema 2 moved the two bulkiest contents out of the tables: the enrichment gene lists (about 1.1 GB) and the pattern markers (4.6 M rows) are now per-dataset artifacts (enrichment_genes, pattern_markers).

Reading it. Open read-only from R with DBI::dbConnect(RSQLite::SQLite(), path, flags = RSQLite::SQLITE_RO), or sqlite3 -readonly. Whole-table scans of the 3.6 GB file over the cluster’s network filesystem are slow from a login node; copy it to a compute node’s local disk for heavy queries.

Design notes

  • Stability without every cell. For each pair of fits of a method, factors are matched 1-to-1 (Hungarian algorithm on loadings cosine; on |cosine| for methods whose factors can flip sign). Rather than store every factor × factor similarity (85% of which were never read), the DB keeps the matches plus context to judge them: each match’s runner-up and margin, statistics of the unmatched similarities per fit pair, and pooled histograms.
  • WGCNA kME in context. For each gene, its correlation with its own module’s eigengene (kME), its best competing module, an analytic p-value, and an empirical p-value against a permutation null (each eigengene’s samples shuffled 100 times), with member / non-member / permutation summaries and histograms per module. The full genes × modules kME matrix is an artifact.
  • Everything computed is kept, including tables the app doesn’t read yet (pattern drivers, markers, redundancy, ICASSO membership, the diagnostics).
  • Method-specific values in long tables (fit_params, fit_metrics, fit_artifacts) rather than per-method columns.
  • Enrichment is stored separately from its jobs. Each enrichment branch keeps its result trimmed to the significant terms; rows are built afterwards, so changing these tables never reruns fgsea.

Conventions

  • Engine: SQLite. Column types are SQLite storage classes: INTEGER, REAL, TEXT.
  • Booleans are INTEGER with CHECK (x IN (0,1)).
  • Timestamps are TEXT in ISO-8601 UTC (utc_now(), e.g. 2026-10-05T16:13:15Z).
  • Creation: the schema is defined in R/db/schema.sql (tables) and R/db/views.sql (views). open_stability_db() in R/db/connect.R creates them on a new DB and stamps PRAGMA user_version. An existing DB with a different version is refused; delete it and rebuild. There are no migrations.
  • Connection pragmas: foreign_keys = ON, journal_mode = WAL, synchronous = NORMAL, busy_timeout = 30000.
  • Who writes: the DB is written by two deployment = "main" targets only.
    • db_<dataset>, via write_dataset_db() in R/targets/db_write.R, writes every table scoped to one dataset in a single transaction.
    • db_cross_dataset, via write_cross_dataset_db() in R/targets/db_write.R, writes the tables that link two datasets (projections, gene_space_agreement).
    • Every other target computes in-memory rows keyed by fit_key (and factor_index). The writer resolves those keys to integer ids.
  • Update semantics:
    • datasets and fits are upserted. fits is matched on fit_key, so a fit keeps its fit_id across rewrites.
    • All child rows of a dataset are deleted and re-inserted on each write.
    • Fits whose fit_key disappeared are deleted, and ON DELETE CASCADE removes their dependents.
  • Abbreviations below: PK primary key, FK → t.c foreign key, CASCADE = ON DELETE CASCADE, UQ part of a UNIQUE constraint, NN NOT NULL, IDX indexed.

Method and fit tables

methods

One row per method registry (R/methods/<method>.R). It holds the method properties that code used to hardcode (PARAM_GRID_METHODS, SIGN_AMBIGUOUS_METHODS, method lists), so queries can filter on them.

  • Rows from: METHOD_MANIFEST (R/lib/method_registry.R::discover_method_registries()).
  • Written by: write_dataset_db() (upsert on method).
Column Type Attributes
method TEXT PK
family TEXT NN; CHECK IN (‘seed_sweep’,‘param_grid’)
sign_ambiguous INTEGER NN; boolean
has_loadings INTEGER NN; boolean (0 for WGCNA)

fits

One row per fitted model, i.e. one row of a method’s parameter grid for one dataset. Failed fits are recorded too, with status = 'failed' and the error message.

  • fit_key is <method>_<hash>, the hash covering the dataset id, the method and the grid row’s parameters, excluding tar_group and the method’s resource_params (R/targets/ingest.R::fit_key()). It is the stable identity shared with the artifact file names, and it is unique across datasets.
  • fit_id is the compact integer used in joins.
  • Rows from: ingest_<method>_<key> (R/targets/ingest.R::ingest_method_fits(), which calls the method’s <method>_ingest$extract() in R/methods/<method>.R). A fit that errored at fit time, or an sPCA fit stopped at its time limit (error = “killed_not_converged …”), is a failed row. representative is set from representatives_<method>_<key> (R/targets/ingest.R::representative_keys(); sPCA from selection_spca_<key>).
  • Written by: write_dataset_db() (upsert on fit_key).

Pair-stability tables

Stability compares every pair of fits of one method within a dataset (all seeds, all ranks).

  • Factor methods use Hungarian matching on loadings cosine (on |cosine| for sign-ambiguous methods). WGCNA matches modules by gene Jaccard.
  • Instead of storing every factor × factor cell, the DB stores the matches plus enough unmatched-cell context (runner-up, null stats, histograms) to judge each match.
  • Statistics over unmatched cells use |value|.
  • Rows from: pairs_<method>_<key> (R/targets/ingest.R::compute_method_pairs(), which calls R/lib/ingest/pairs.R::compute_factor_pairs() or compute_wgcna_pairs()).
  • Written by: write_dataset_db().

match_scores

The similarity of a matched pair under each metric, with its runner-up context.

  • runner_up is the largest |value| among the unmatched cells in factor_a’s row and factor_b’s column.
  • margin = |value| − runner_up. Positive means the match is clearly better than any alternative.
  • Metrics: cosine, pearson and spearman for factor methods; jaccard for WGCNA.
Column Type Attributes
match_id INTEGER PK (with metric); FK → factor_matches.match_id CASCADE
metric TEXT PK (with match_id); CHECK IN (‘cosine’,‘pearson’,‘spearman’,‘jaccard’)
value REAL NN; signed
runner_up REAL NULL when the fit pair has no unmatched cell in that row/column
margin REAL

fit_pair_null

Background (“null”) distribution of the unmatched cells of one fit pair under one metric: the similarity level a non-match reaches.

Column Type Attributes
fit_pair_id INTEGER PK (with metric); FK → fit_pairs.fit_pair_id CASCADE
metric TEXT PK (with fit_pair_id); CHECK IN (‘cosine’,‘pearson’,‘spearman’,‘jaccard’)
n INTEGER NN; number of unmatched cells
mean REAL
sd REAL
median REAL
p95 REAL
max REAL

similarity_histograms

Fixed-bin histograms (20 bins over |value| in [0, 1]) of matched and unmatched cells, pooled over all fit pairs of a method at one pair of levels.

  • level is rank for factor methods and power for WGCNA, with level_a <= level_b.
  • These are the plotted distributions behind fit_pair_null.
Column Type Attributes

method TEXT PK; FK → methods.method

WGCNA tables

gene_modules

One row per gene per WGCNA fit: its module assignment (0 = unassigned) and its own-module kME, with context.

  • The full genes × modules kME matrix is the fit’s kme artifact.
  • Rows from: wgcna_fit_diag_<key>, a dynamic branch per WGCNA fit (R/targets/diagnostics.R::wgcna_fit_diagnostics()). The module assignment comes from ingest_wgcna_<key>.
  • Written by: write_dataset_db().

Cross-dataset tables

Written by db_cross_dataset (R/targets/db_write.R::write_cross_dataset_db()). It runs after every db_<dataset>, so fit ids on both sides are resolvable.

projections

projectR projection of a source fit’s loadings onto another dataset’s matrix, either a related timepoint (within_dataset) or another cohort (cross_dataset).

  • The projected matrix is in the file at path.
  • Rows from: projectr_<key>, one branch per (source dataset, target dataset) (R/targets/projections.R::projection_rows(), running R/ingest_jobs/projectr_job.R), joined at write time to projection_scores_<key> (projection_scores()), the centred scores.
  • Scores. projectR’s R² is taken against the raw expression, which the mean expression profile alone scores about 0.93 on (a cross-family projection also fits an intercept), so it is not stored; each projection’s per-sample values are in the file at path. The stored scores are centred: the target is centred by its gene means and sample offsets, the loadings columns are centred, no intercept is fitted, and the R² is pooled over the target (transfer_r2). native_r2 is the most any basis of the same size could explain (the target’s own top principal components), relative_r2 = transfer_r2 / native_r2 is the score to compare across methods and projection types, and null_r2 is transfer_r2 with the loadings’ genes shuffled (about 0). All loadings columns are used (n_components; PCA: its maximum rank).

variance_summary

One row per dataset with its own design: the headline repeated-measures numbers.

  • Fit: n_genes, n_genes_failed, n_factor_genes (genes the factor analysis uses), share_singular, max_colinearity, dupcor_consensus (limma’s genome-wide subject correlation).
  • Gene-level shares: between_median, time_median, residual_median, technical_median (median over genes; between = subject + subject-level variables, time = time + group × time); repeatability_median (between / (between + residual)); time_within_median (time / (time + residual)); share_time_gt05/10/20 (genes with time above 5/10/20%).
  • Variance-weighted shares: between_vw_*, time_vw_*, residual_vw_* over all genes (_all), the factor-analysis genes (_factor_genes) and the top 8,000 by variance (_top).
  • Within-person change (subjects sampled more than once; each later sample minus the subject’s first): n_subjects_repeated, n_changes, change_pc1_share (share of the change on its first PC), change_pc1_cor_nl, median_r2_nl_all / _factor_genes and median_r2_technical_all / _factor_genes (median R² of each gene’s change against the change in composition or in the technical covariates).
  • Sample checks: rho_pc1_nl, rho_sd_nl, rho_mean_nl (Spearman, against the neutrophil-lymphocyte score), rho_sd_technical, rho_mean_technical (against control mean or library size), n_control_probes, control_probes (which), control_factor_fraction, sex_separation, sex_agreement, n_subjects_sex_discordant, nl_subject_fraction, nl_time_fraction, nl_group_fraction.
  • Run: vp_seconds, dream_seconds, fitted_at.

variance_terms, variance_categories, variance_bins

  • variance_terms (dataset_id, term): each model term’s category (‘subject’, ‘subject-level’, ‘time’, ‘group x time’, ‘group’, ‘technical’, ‘covariate’, ‘residual’, or ‘derived’ for the between-subject and time totals) and its distribution over genes: n_genes, mean, q10, median, q90, share_gt05, share_gt10.
  • variance_categories (dataset_id, category): present, mean, median, and variance-weighted shares vw_all, vw_factor_genes, vw_top.
  • variance_bins (dataset_id, binning, bin): median between-subject (between_subject), time and residual fractions by expression quartile (binning = 'expression_quartile', Q1 = lowest) and by variance rank ('variance_rank').

trait_variance, composition_correlations

  • trait_variance (dataset_id, trait, term): the sample-level traits (expression mean/sd/q90, PC1–3, marker scores, control mean, library size, TMM factor) through the dataset’s variance formula: fraction and category per term.
  • composition_correlations (dataset_id, x, y): Spearman rho and p-value between every pair of those traits.

de_contrasts

One row per dream contrast or joint test (dataset_id, contrast): kind (‘pairwise’ or ‘omnibus’), readable (the levels compared, or the contrasts tested jointly), n_genes, n_fdr05. Full tables are the de_results artifact.

factor_variance, factor_variance_models

  • factor_variance (factor_id, term): every fitted factor’s sample scores through the dataset’s variance formula (a subset: its parent’s, without subject and time): category and fraction per term. FK → factors.factor_id CASCADE. From factor_vp_<method>_<key> (R/targets/variance_explore.R::factor_variance_partition()).
  • factor_variance_models (dataset_id, method): the formula used and the number of factors.

variance_time_genes, time_gene_recurrence

  • variance_time_genes (dataset_id, symbol): genes with time + group × time above 10% of their variance, with their time (time_all) and between-subject (between_subject) fractions.
  • time_gene_recurrence (symbol): in how many datasets, and which, a gene is time-driven. Written by write_cross_dataset_db() from variance_explore.
