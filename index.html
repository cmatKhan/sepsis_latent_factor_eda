Overview

This project measures how stable the latent factors found in sepsis gene-expression datasets are, and compares them across datasets. Six methods are fit to every dataset – PCA, NMF, CoGAPS, sparse PCA (sPCA), ICA and WGCNA – across random seeds and across their rank or sparsity parameters. Stability, enrichment, projections and diagnostics are then written to one SQLite database, which a Shiny app browses.

One targets pipeline (_targets.R) does all of it, with the heavy steps running as SLURM jobs through crew.cluster:

  1. Matrices. Each dataset’s config says how to build its genes × samples matrix from the raw data (Data).
  2. Fits. Each method’s parameter grid is fit, one fit per grid row (Methods).
  3. Repeated measures. For datasets with a study design, a variance partition and differential expression per gene, and sample checks (leukocyte composition, technical scale, recorded vs inferred sex) (Methods).
  4. Ingestion. Fits are compared with each other (stability), enriched, projected onto the other datasets, described by the repeated-measures model and summarized, then written to the database (Database).
  5. App. A Shiny app browses the database (Launching the app).

targets re-runs only what a change invalidates: editing one dataset’s config rebuilds that dataset only, editing one method rebuilds that method only (Running the workflow).

Layout

Path What
_targets.R the pipeline: sources the code, builds the targets for every dataset in config/pipeline.yml
config/pipeline.yml datasets to build, data root, DB path, SLURM resources per method
config/<dataset>_config.yml one dataset: data paths, its study design (design:) and each method’s parameter grid
config/composition_markers.yml marker genes for the per-sample leukocyte composition scores
config/dataset_families.yml which datasets are timepoints of the same cohort
R/methods/ one file per method: fit function, <name>_registry (fitting) and <name>_ingest (ingestion)
R/lib/ config reading, data paths, matrix loading, study designs (design.R), expression input for the variance models (expression.R), method discovery
R/lib/ingest/ the computations behind the DB: similarity, factor/module pairs, redundancy, ICASSO, pattern drivers, gene-id mapping
R/targets/ target factories, SLURM controllers, ingestion, enrichment, projections, diagnostics, the repeated-measures analysis (variance*.R, composition.R), DB writers
R/ingest_jobs/ the enrichment and projectR job functions
R/db/ the DB schema (schema.sql, views.sql) and open_stability_db()
R/preprocessing/ one matrix-building script per dataset
R/explore/ interactive scripts over stored results (variance_by_time.R)
app/ the Shiny app
run_pipeline.sbatch runs tar_make() as a SLURM job
